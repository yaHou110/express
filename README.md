# Vala Commerce | والا کامرس

پلتفرم پیشرفته و یکپارچه تجارت الکترونیک — فروشگاه‌اینترنتی فارسی (RTL) با تمرکز بر انضباط محاسبات مالی، ماشین حالت تغییرناپذیر سفارشات و انبارداری بدون کسری.

**نسخه آنلاین:** https://valakala.vercel.app/

---

## قابلیت‌ها

### فروشگاه (Storefront)
- صفحه اصلی با هیرو پرچمداری، شبکه دسته‌بندی و گرید محصولات برگزیده
- کاتالوگ محصولات با جستجو، فیلتر دسته/برند، فیلتر موجودی و مرتب‌سازی
- صفحه جزئیات محصول با انتخاب تنوع (Variant)، مشخصات فنی و نظرات
- مقایسه مشخصات محصولات در یک مودال سراسری
- سبد خرید، فرآیند چندمرحله‌ای تسویه، کد تخفیف و انتخاب روش ارسال
- حساب کاربری مشتری: سفارشات، علاقه‌مندی‌ها و آدرس‌ها

### پنل مدیریت (Admin)
- داشبورد شاخص‌ها: GMV، سفارشات، هشدارهای کسری انبار و اسناد دفتر کل
- مدیریت سفارشات با گذار وضعیت از طریق ماشین حالت
- مدیریت موجودی و انبارهای فیزیکی
- دفتر کل مالی دوطرفه (Double-entry Ledger)
- تنظیمات و Feature Flags برای روشن/خاموش کردن ماژول‌ها

### پیش‌نمایش‌های سازمانی (Enterprise Previews)
- مارکت‌پلیس چندفروشندگی، فروش عمده B2B و توزیع چندانباره

## شروع سریع

```bash
npm install
npm run dev
```

سپس http://localhost:3000 را باز کنید.

## اسکریپت‌ها

| اسکریپت | توضیح |
|---|---|
| `npm run dev` | اجرای محیط توسعه |
| `npm run build` | ساخت خروجی پروداکشن |
| `npm start` | اجرای سرور پروداکشن (`next start`) |
| `npm run start:standalone` | اجرای خروجی `output: 'standalone'` (پیشنهادی برای پروداکشن) |
| `npm run lint` | اجرای ESLint روی کل پروژه |
| `npm run clean` | پاک کردن پوشه `.next` |

> چون `next.config.ts` روی `output: 'standalone'` تنظیم است، برای اجرای پروداکشن محلی از `npm run start:standalone` استفاده کنید؛ `next start` در این حالت هشدار می‌دهد.
>
> روی Vercel نیازی به هیچ‌کدام نیست و پلتفرم خروجی را خودش می‌سازد.

## ساختار پروژه

```
app/                     لایه Next.js (layout، صفحه اصلی، استایل سراسری)
components/
  layout/                هدر و فوتر فروشگاه
  storefront/            کاتالوگ، سبد خرید، تسویه، حساب کاربری، مقایسه
  admin/                 داشبورد، سفارشات، انبار، دفتر کل، Feature Flags
  enterprise/            پیش‌نمایش‌های B2B، مارکت‌پلیس و چندانباره
domain/                  هسته دامنه (مستقل از UI)
  types.ts               مدل داده: محصول، تنوع، سفارش، اسناد دفتر کل، فلگ‌ها
  money.ts               محاسبات پولی روی اعداد صحیح
  stateMachine.ts        گذارهای مجاز وضعیت سفارش
  features.ts            فلگ‌های پیش‌فرض و متادیتای ماژول‌های پرمیوم
data/                    داده اولیه دمو (کاتالوگ و state آغازین)
services/                کانتکست و reducer فروشگاه
hooks/ · lib/            هوک‌ها و ابزارهای عمومی
```

## معماری دامنه

- **پول:** مقادیر مالی هرگز روی `float` محاسبه نمی‌شوند؛ `domain/money.ts` روی مقادیر صحیح با واحد تومان کار می‌کند تا خطای ممیز شناور در فاکتور، مالیات و تخفیف رخ ندهد.
- **سفارش:** وضعیت سفارش فقط از طریق گذارهای مجاز `domain/stateMachine.ts` تغییر می‌کند و `transitionOrderStatus` در صورت گذار نامعتبر خطا برمی‌گرداند.
- **مالی:** هر تراکنش به‌صورت سند دوطرفه در دفتر کل ثبت می‌شود.
- **انبار:** تخصیص موجودی در لحظه خرید انجام و از فروش کالای ناموجود جلوگیری می‌شود.

## متغیرهای محیطی

فایل `.env.example` را به `.env.local` کپی کنید:

```bash
cp .env.example .env.local
```

| متغیر | توضیح |
|---|---|
| `APP_URL` | آدرس عمومی سایت، برای لینک‌های self-referential |
| `GEMINI_API_KEY` | کلید Gemini API؛ در حال حاضر مصرف‌کننده‌ای در کد ندارد و برای توسعه‌های آینده رزرو شده است |

npm run build   # بررسی سلامت بیلد پیش از پوش
